Vanilla Engine Docs
Editor guide and Vanillalua reference

        
      

      

        
 Up to date

        

        
Vanilla Engine is a browser 3D editor with a built-in scripting language, Vanillalua. This guide has two parts: how the editor works, then everything the language supports. It is written for engine version 2.2.0.2.

        
Editor overview

        
The editor is built from a few panels. Everything you build lives in one of three spaces in the Explorer.

        
PartWhat it does

          
ExplorerLists the World, Storage and Scripts spaces. Use the + on a space to create a Rectangular Prism (prism6), a World Settings or a Script. Storage holds objects kept for scripts and never renders; only World renders.

          
ViewportThe 3D view. Select, Move and Scale modes work here.

          
PropertiesEdits the selected instance: name, position, size, physics flags, script options.

          
Tab barWorld is always open. Scripts open as tabs over the viewport.

        

        
Multi-select: hold Shift and click to add or remove single objects. Hold Ctrl (Cmd on Mac) and click to select every object between your last click and the one you click. Copy, cut, paste, delete and dragging then apply to all selected objects.

        
Hover an instance in the Explorer and press the three-dot button for Rename, Copy, Paste, Cut, Delete and Move Camera To.

        
Camera and selection

        
The camera looks like a first-person view: the horizon stays level and dragging turns your head up, down, left and right. There is no momentum, so it stops the moment you let go. Move with W A S D.

        
In Settings, Drag to move turns the camera with the left mouse button and Right click to move uses the right button. The camera is locked while you drag a gizmo handle.

        
Move, Scale and Offset

        
    
          
  • Select picks an instance in the viewport or the Explorer.
    • 
          
  • Move shows an arrow on each of the six sides of the selected block.
    • 
          
  • Scale shows a sphere on each of the six sides.
    • 
        

        
Handles are always drawn on top of the scene at about a third of the block's size. The Offset box next to Run sets the step for both tools in Vanillameters. It starts at 0.5; set it to 0 for free, unstepped movement.

        
Run and Stop

        
Run works like Roblox Studio: the world is snapshotted, physics and scripts run live, and Stop restores the snapshot exactly as it was. Anything scripts create or change during a run is discarded on Stop, and global variables are cleared.

        
Heads up: saving, opening a world and starting a new one are blocked while a simulation runs. Stop first.

        
World Settings

        
A World Settings instance controls the environment. It appears under World and is editable in Properties.

        
PropertyRangeDefault

          
TimeOfDay0 to 24 hours, drives the sky14

          
Gravity0 to 1000 m/s². Presets: Earth 9.8, Moon 1.62, Space 0, Jupiter 24.89.8

          
KillLayerAny height. Moving objects that fall below it are deleted-5000

        

        
There is no invisible ground at y = 0. Objects fall until they land on something solid or pass the kill layer.

        
File menu and .vnw files

        
The File menu in the top bar saves and opens whole worlds. A world file (.vnw) is plain JSON holding everything in World, Storage and Scripts, including script source. Engine-owned objects such as the Viewfinder are not saved.

        
CommandWhat it does

          
Save in browser Ctrl SKeeps one save in this browser's local storage. Saving again overwrites it.

          
Download as .vnw Ctrl Shift SDownloads World.vnw to share or back up.

          
Open browser saveReplaces the current world with your browser save.

          
Open .vnw file…Replaces the current world with a file you choose. Invalid files are rejected with a message and nothing changes.

          
New empty worldClears World, Storage and Scripts, leaving one World Settings.

        

        
Opening and creating ask for confirmation first because they replace everything. There is no undo, so save before you open another world.

        
Childing

        
Any instance can be a child of another instance. The Explorer shows children indented under their parent, with an arrow to collapse them.

        
    
          
  • Drag a row onto another row to make it a child. Drag it onto a space name to move it back to the top level of that space.
    • 
          
  • Use Add Child… or Paste as Child in an instance's three-dot menu to create or paste something directly inside it.
    • 
          
  • Deleting a parent deletes all of its children. Copy, cut and paste carry children along.
    • 
          
  • Reorder by dropping on the top or bottom edge of a row (a line shows where it will land). Dropping on the middle of a row makes a child.
    • 
        

        
Children live in the same space as their parent and keep their own position; they do not move with the parent. A script placed under an object, anywhere inside World or Scripts, runs like any other script and can reach that object with script.Parent.

        
Settings

        
SettingWhat it does

          
Camera move methodChoose whether dragging with the left button or the right button turns the camera.

          
Show UID instead of nameThe Explorer lists instances by unique ID.

          
Default object namesSets the name for each new Rectangular Prism, Script and World Settings. Empty restores the default.

          
Script colorationTurns syntax coloring in the script editor on or off.

          
Pre-includeAdds call Scripts, get Instance, call World, call Storage or get Scripting to every script without typing them. The first two are required for a script to run.

          
Light modeSwitches the editor and viewport palette.

        

        
Settings are stored in this browser and are not part of a .vnw file.

        
The script editor

        
Create a Script from a space's + button and double-click it to open it as a tab. The editor shows line numbers on the left, your code in the middle, and warning and error markers on the right. The Output panel below shows print results and runtime errors. Tab indents.

        
Script properties split into Execution and Miscellaneous:

        
    
          
  • Script type: Local or Server (see Script types and running).
    • 
          
  • Run when: Simulation start, Client join or Manual call by another script.
    • 
          
  • Language: Vanillalua or JSON. JSON scripts hold data, are checked for valid JSON and cannot run.
    • 
        

        
1. A first script

        
Every Vanillalua script should begin by loading the Scripts space and the Instance module. Add other spaces with call when you need to access them.

        
call Scripts
call World
get Instance

local block = Instance.create("prism6", World)
block.Position = vanilla3D.Position(0, 10, 0)
print("Created:", block)

        
call World loads the World space. get Instance loads the instance API, and get Scripting loads scripting utilities for UID lookup and reassignment. Setup lines belong at the top of the script.

        
2. Variables: local and global

        
local name = value creates a variable scoped to the current script block. A variable assigned without local is a global variable: all scripts can read it while the simulation is running.

        
call Scripts
get Instance

local privateCount = 1
sharedCount = 10
print(privateCount)
print(sharedCount)

        
Global write permissions: the script that first creates a global may update it, and any Server script may update any global. Other Local scripts can read globals but cannot change them. Use a Server script for values that need to be centrally controlled. Global variables are runtime state and are cleared when a new simulation starts or the simulation stops.

        
Use clear, descriptive names for globals to avoid accidentally sharing the same name between scripts. Local variables are best for temporary values and implementation details.

        
# Server script
sharedScore = 0

# Any script can read this:
print(sharedScore)

# The script that created sharedScore can update it,
# and Server scripts can update it too.
sharedScore = sharedScore + 1

        
3. Values and types

        
    
          
  • Numbers: 12, 3.5, 0.25. Decimal literals support up to two digits after the decimal point.
    • 
          
  • Strings: "hello" or 'hello'. Use 
 for a newline and 	 for a tab inside a string.
    • 
          
  • Booleans: True and False.
    • 
          
  • Nil: nil represents no value.
    • 
          
  • Instances: references to objects in the scene, such as the result of Instance.create().
    • 
          
  • Vectors: three-number values used for positions and sizes.
    • 
        

        
Comments start with # and continue to the end of the line.

        
4. Printing output

        
Use print(...) to send values to the Output panel. You can print strings, numbers, variables, instances, vectors, and multiple values.

        
call World
get Instance
local score = 125
local block = Instance.create("prism6", World)
print("Score:", score)
print("Block ID:", block)
print("Position:", block.Position)

        
Instances print their unique ID, such as Cobalt092. Multiple arguments are separated in the output. If an instance has been deleted, its printed value is deleted instance.

        
5. Waiting and timed scripts

        
wait(seconds) pauses the current script for the specified number of seconds. The argument must be a non-negative number with up to two decimal places. Waiting yields to other scripts and the simulation; it does not freeze the whole editor.

        
call Scripts
call World
get Instance

local block = Instance.create("prism6", World)
block.Position = vanilla3D.Position(0, 0, 0)
for i in 1, 5 do
    block.Position.Y = block.Position.Y + 1
    print("Step", i, "Y =", block.Position.Y)
    wait(0.5)
end

        
Use wait(0) to yield without an intentional delay. A long-running while loop yields between iterations, so other scripts can continue running.

        
6. Operators

        
    
          
  • Math: +, -, *, /, %
    • 
          
  • Comparisons: ==, ~= or != (not equal), <, >, <=, >=
    • 
          
  • Logic: and, or, not
    • 
          
  • Grouping: parentheses such as (a + b) * 2
    • 
          
  • String joining: use + when at least one operand is a string, e.g. "Score: " + score.
    • 
        

        
Math operators require numbers, except vector addition/subtraction and vector multiplication by a number. In conditions, nil and False are false-like; other values are true-like.

        
7. Conditions

        
local temperature = 18
if temperature >= 25 then
    print("Warm")
else
    print("Cool")
end

        
Conditions use if, optional else, and end. Comparisons can be combined with and, or, and not. There is no elseif; nest another if inside else instead.

        
8. Loops

        
A numeric for loop includes both its start and end values:

        
for i in 1, 4 do
    print("Iteration", i)
end

        
A while loop repeats while its condition remains true. Make sure something changes the condition so the loop can finish.

        
local count = 0
while count < 3 do
    count = count + 1
    print(count)
    wait(0.25)
end

        
9. Spaces and instance lookup

        
Available spaces are World, Storage, and Scripts. Load each with call before using it. Existing instances must be accessed by their unique ID (UID), not by their display name. Use Instance.GetUID(name) to find an ID by object name.

        
call World
get Scripting
get Instance

local blockUID = Instance.GetUID("Block")
local block = World.blockUID
print(block.Name)

        
When a dot member on a Space matches a local variable, its string value is treated as the UID. Bracket lookup also works: World[blockUID]. You can pass the Space to GetUID when names are duplicated, for example Instance.GetUID("Block", World).

        
10. The Instance module

        
    
          
  • Instance.create(type, space) — creates and returns an instance. Supported types: "prism6", "script", and "worldsettings".
    • 
          
  • Instance.duplicate(instance) — duplicates an instance in its current space.
    • 
          
  • Instance.duplicate(instance, space) — duplicates it into a chosen loaded space.
    • 
          
  • Instance.delete(instance) — deletes the instance. References to it become deleted references.
    • 
          
  • Instance.GetUID(name) — returns the unique ID of an existing instance with that display name. Optionally pass a Space as the second argument to disambiguate duplicates.
    • 
          
  • Instance.SetUID(oldUID, newUID) — changes an instance's unique ID. The new UID must be unique and contain only letters and numbers, starting with a letter.
    • 
        

        
call World
get Instance

local original = Instance.create("prism6", World)
original.Position = vanilla3D.Position(0, 3, 0)
local copy = Instance.duplicate(original, World)
copy.Position = vanilla3D.Position(2, 3, 0)
print("Original:", original)
print("Copy:", copy)
Instance.delete(copy)

        
Find and change a unique ID

        
call World
get Scripting
get Instance

local blockUID = Instance.GetUID("Block")
local block = World.blockUID

Instance.SetUID(blockUID, "Ashburn534")
blockUID = Instance.GetUID("Block")
block = World.blockUID
print(blockUID)
print(block)

        
SetUID rekeys the existing instance; it does not rename the visible Name property. Refresh the UID variable after changing it, then retrieve the instance again. If more than one object has the same name, provide its Space to GetUID.

        
11. Properties and vectors

        
Read or set properties using instance.Property. Properties are validated by the engine, so a property expects the correct kind of value.

        
Applies toProperties

          
Every instanceName (string), Type (read-only), Parent (a Space or an instance)

          
Prism blocksPosition, Size (vectors, each axis at least 0.05 for Size), Locked, Anchored, ReactsToPhysics, Collidable, Wireframe, FaceColoring, ShowLabels (True or False)

          
World SettingsTimeOfDay (0 to 24), Gravity (0 to 1000), KillLayer (number)

          
ScriptsRun, a function: myScript.Run() starts that script

        

        
vanilla3D.Position(x, y, z) and vanilla3D.Size(x, y, z) create three-component vectors. Vector axes are uppercase X, Y, and Z. For a prism, Position maps to its world coordinates; Size maps to width, height, and length respectively.

        
call World
get Instance
local block = Instance.create("prism6", World)
block.Position = vanilla3D.Position(2, 5, 0)
block.Size = vanilla3D.Size(2, 1, 3)
block.Anchored = True
print(block.Position.X, block.Position.Y, block.Position.Z)

        
11b. Parents and the script variable

        
Inside every running script, script is a built-in variable that always refers to the script itself. Its Parent is the object the script sits under, or a Space if it is not inside an object.

        
call Scripts
get Instance

local part = script.Parent
part.Anchored = True
print("Controlling", part.Name)

# Reparent: put a new script inside the block
local child = Instance.create("script", World)
child.Parent = part

        
Read Parent from any instance. Assign it an instance or a Space to move it. An instance cannot become its own parent or a child of its own descendant. If a script is not inside an object, script.Parent is its Space, such as Scripts.

        
12. Script types and running

        
    
          
  • Server: trusted script type for shared/global updates. Server scripts can modify any global variable.
    • 
          
  • Local: can read global variables and modify only globals it originally created.
    • 
          
  • Run When: Simulation: runs when Run starts the simulation.
    • 
          
  • Run When: Join: reserved for join-trigger behavior if supported by the current project workflow.
    • 
          
  • Run When: Manual: starts only when manually invoked, for example through the script's Run property.
    • 
        

        
When the simulation starts, Server scripts begin before Local scripts. A JSON script cannot be run. Stopping the simulation stops active script tasks and restores the scene snapshot from before Run. Runtime globals are cleared as part of ending the simulation.

        
13. Full example: shared status and moving block

        
# Server script
call Scripts
call World
get Instance

moveStatus = "Starting"
local block = Instance.create("prism6", World)
block.Position = vanilla3D.Position(0, 1, 0)
moveStatus = "Moving"
for step in 1, 6 do
    block.Position.Y = block.Position.Y + 1
    print(moveStatus, "step", step, "position", block.Position)
    wait(0.25)
end
moveStatus = "Finished"
print(moveStatus)

        
14. Common errors and fixes

        
    
          
  • Missing call Scripts: add call Scripts at the top of every Vanillalua script, or turn on pre-include for it in Settings, Scripting.
    • 
          
  • Missing get Instance: add get Instance at the top if you use instance functions; the editor currently requires this setup line for every Vanillalua script.
    • 
          
  • Space not loaded: add call World, call Storage, or call Scripts before referencing that space.
    • 
          
  • Unknown variable: check spelling and whether the value is local to another script. Use a global assignment (without local) to share a value.
    • 
          
  • Global write denied: only the script that created the global or a Server script can update it.
    • 
          
  • Invalid property value: check that the property name and value type match, e.g. numeric Gravity or boolean Anchored.
    • 
          
  • Invalid wait: use one non-negative number, with no more than two decimal places.
    • 
          
  • Instance deleted: confirm that the instance has not been deleted before reading or changing it.
    • 
        

        
15. Quick reference

        
call Scripts       # Load Scripts space
call World         # Load World space
call Storage       # Load Storage space
get Instance       # Load instance API
local x = 3        # Local variable
sharedValue = 3    # Shared global variable
print(x, sharedValue)
wait(0.5)          # Pause for half a second
if x > 1 then print("yes") else print("no") end
for i in 1, 3 do print(i) end
Instance.create("prism6", World)
Instance.duplicate(block, World)
Instance.delete(block)
vanilla3D.Position(0, 1, 0)
vanilla3D.Size(1, 2, 1)

        
Tip: test scripts with the Output panel open. Use short loops, add print() checkpoints, and introduce waits when you want to observe changes over time.
