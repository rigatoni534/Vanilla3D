Vanilla EngineDocumentation

        
      

      

        
 Up to date

        

        
Vanilla Engine is a browser 3D editor with a built-in scripting language, Vanillalua. This guide has two parts: how the editor works, then everything the language supports. It is written for engine version 4.0.0.0 Golden.

        
Editor overview

        
The editor is built from a few panels. Everything you build lives in one of the spaces in the Explorer.

        
PartWhat it does

          
ExplorerLists the World, Storage, Scripts, UI and Communications spaces, plus Players and Engine. Use the + on a space to create a Rectangular Prism (prism6), a Wedge, a Cylinder, a Ball, a Sound, a Highlight, a Light, a Human, a World Settings or a Script; Communications offers ClientSocket, ServerSocket, PeerConnection and GroupConnection. Storage holds objects kept for scripts and never renders; only World renders. UI holds the screen interface.

          
ViewportThe 3D view. Select, Move and Scale modes work here.

          
PropertiesEdits the selected instance: name, position, size, physics flags, script options.

          
Tab barWorld is always open. Scripts open as tabs over the viewport.

        

        
Communications holds the connections a world uses. Choose + on the Communications space to add one. They are saved with the world, and nothing is sent or received yet: the editor sets them up, and the network side comes later.

        
InstanceWhat it is forProperties

          
ClientSocketThe server's end of one player's connection, so the server can send messages to that client.Active, Client (IPv4), Player (a Player in Players), Bandwidth in kbps. 0 is Uncapped.

          
ServerSocketThe client's end of the connection to the server. A world has one server that the clients talk to.Active, Bandwidth in kbps (4096 by default), MaxClients. Keep MaxClients at the world max player count.

          
PeerConnectionA direct connection between two peers, for games that do not need a server in the middle.Active, EntryPassword, Client1 and Client2 (IPv4), and Player1 and Player2 (Players in Players, like ClientSocket's Player).

          
GroupConnectionA peer connection for any number of clients. Add each client in Properties; there is no client limit.Active, EntryPassword, and a Clients list of IPv4 addresses and players.

        

        
Connections cannot be given children and cannot be moved out of Communications. Drag them within the space to reorder them.

        
Multi-select: hold Shift and click to add or remove single objects. Hold Ctrl (Cmd on Mac) and click to select every object between your last click and the one you click. Copy, cut, paste, delete and dragging then apply to all selected objects.

        
Shortcuts: Ctrl+C, X and V copy, cut and paste; Ctrl+Shift+V pastes inside the selection; Ctrl+D duplicates; Ctrl+A selects all; Delete or Backspace deletes; Space renames; F moves the camera to the selection; Ctrl+M groups into a model; Ctrl+U unions; Ctrl+Shift+U intersects; Ctrl+Z undoes and Ctrl+Shift+Z redoes. Shortcuts pause while you type, while a menu is open and while the simulation is running, so Space still jumps and Backspace never leaves the page. Undo keeps up to 100 world snapshots for editor commands.

        
Hover an instance in the Explorer and press the three-dot button for Rename, Copy, Paste, Cut, Delete and Move Camera To.

        
A Rectangular Prism also has a Color in its Render section: pick one with the color box or type a hex code such as #ff8800. Turning on Face coloring overrides it, because each face then shows its own debug color.

        
Every block, wedge, cylinder and union has an Outline switch in Render for the thin dark line drawn along its edges. The cylinder is treated as one round surface: it gets a single outline around each end rather than a line at every facet, and its Size scales its shading with it.

        
Camera and selection

        
The camera looks like a first-person view: the horizon stays level and dragging turns your head up, down, left and right. There is no momentum, so it stops the moment you let go. Move with W A S D.

        
In Settings, Drag to move turns the camera with the left mouse button and Right click to move uses the right button. The camera is locked while you drag a gizmo handle.

Shortcuts pause while you type, while a menu is open and while the simulation is running, so Space still jumps and Backspace never leaves the page.

Move, Scale and Offset

        
    
          
  • Select picks an instance in the viewport or the Explorer.
    • 
          
  • Move shows an arrow on each of the six sides of the selected block.
    • 
          
  • Scale shows a sphere on each of the six sides.
    • 
        

        
Handles are always drawn on top of the scene at about a third of the block's size. The Offset box next to Run sets the step for both tools in Vanillameters. It starts at 0.5; set it to 0 for free, unstepped movement.

        
The Rotate tool (key 4) turns a prism or ball. Each axis has a double-headed curved arrow; drag it to turn the shape about that axis. The Rotation box beside Offset sets how many degrees the arrows snap to (45 by default, 0 for free turning). Rotation is also in the Properties panel as three numbers. The turn about Y is applied first, then the tilt about X, then the roll about Z, and each arrow edits exactly its own number. Physics treats a tilted prism as the box around it, and a tilted prism still blocks balls at its real angle. Models cannot be rotated yet.

        
User interface

        
The UI space is the player's screen. It is drawn over the viewport rather than in the 3D world, and it is made of six instances:

        
InstanceWhat it is for

          
frameA box to group other elements in. It can clip whatever sits outside it.

          
textText on the screen: a score, a label, a message.

          
buttonA pressable element. While the simulation runs it fires its Clicked event for scripts.

          
imageA picture from a URL, stretched to its box.

          
inputA text field the player types into. Pressing Enter fires Submitted with the text.

          
progressbarA bar that fills from 0 to 100%. It can be Straight or Circular, with its own fill color, transparency and blur, and it can hold other UI elements as children.

        

        
Size and position are percentages. Position is the centre of the element, so 50, 50 is the middle of the screen, and Size is the part of what it sits in that the element covers. A strip across the top is a position of 50, 2.5 with a size of 100, 5. An element inside a Frame or a ProgressBar is placed in percentages of that element.

        
Previewing. Select any UI instance, or the UI space itself, and the whole interface appears in the viewport so you can lay it out against the scene. Selecting something else hides the preview again unless Settings > Interface > Always show UI is on.

        
Editing. With Move active, press on an element in the viewport and drag it; it snaps to a 1% grid and a guide line appears only for the position it is snapping to. With Scale active, each corner has a handle: drag a corner diagonally to scale evenly, or mostly sideways or up and down to change only the width or only the height. The opposite corner stays where it is. Every number is also in Properties. The snap grid is 1% by default; Settings > Interface can set it to 0.5%, 2% or 5%.

        
Run. The UI is the server end of the interface. When a player joins in the simulation, that player takes it: the elements move inside the Player instance in Players, keeping their UIDs, and are drawn for the player. Buttons and inputs work there. Scripts reach them through the player, for example player.UI.Score.Text = "10", or through a reference they took before the join. Stop puts everything back in the UI space.

        
Scripts on the interface. A Script can be a child of a UI element: create one with Add Child… on the element, or drag one into it. A script created that way starts as Local, because interface code belongs to the player's side, and it runs when the simulation starts. script.Parent is the element it sits in. A script cannot sit at the top of the UI space on its own; it must be inside an element, and it moves with that element when a player takes the interface.

        
Frame blur. A Frame can frost what is behind it with Background blur and soften its stroke with Border blur. Both are 0 to 20 pixels; border blur needs a border width. They are saved with the world and exposed to scripts as BackgroundBlur and BorderBlur.

        
ProgressBar. A ProgressBar has a background, a shape (Straight or Circular), and a fill with its own Length (0 to 100%), Fill color, Fill transparency and Fill blur. The background can also blur what is behind it. Straight fills from the left; Circular is a ring that fills clockwise from the top. For a true circle, set its Width and Height equal. Child UI elements sit on top of the fill, so text can be placed inside a bar.

        
Run and Stop

        
Run works like Roblox Studio: the world is snapshotted, physics and scripts run live, and Stop restores the snapshot exactly as it was. Anything scripts create or change during a run is discarded on Stop, and global variables are cleared.

        
Heads up: saving, opening a world and starting a new one are blocked while a simulation runs. Stop first.

        
Playing worlds

        
The Player page opens a .vnw file from your computer, a drag-and-drop, the last played world, or an https URL. It shows the world name, creator and instance and script counts, and it asks you to confirm that you trust the world before its scripts run. The world is kept in this browser; opening the page again offers it as the last world.

        
Play Solo opens the world in play mode. The editor panels are hidden and the simulation starts immediately; Escape opens Pause, Resume returns to the game and Leave game goes back to the Player page. Play mode uses the same engine, physics, scripts and player controller as the editor.

        
Materials

        
Every 3D shape has a Material in its Render section. The material changes the surface pattern and how highlights catch it; Color still tints the result, so a brick wall can be blue and a grass floor still takes the colour you choose. Default maps to Plastic, and old worlds are migrated to Plastic only where a material is missing. Materials are visual only: they do not change mass or collision.

        
MaterialWhat it looks like

          
PlasticSmooth moulded surface. The default for every new shape.

          
GlassCool and glossy, with a bright fresnel edge and strong reflection.

          
MetalBrushed metal with a sharp, strong highlight.

          
GrassMottled green blades with a matte finish.

          
BrickStaggered courses with pale mortar lines.

          
TileSquare tiles with grout lines and a light sheen.

          
CarpetFine woven fibres, soft and matte.

          
WoodWarm planks with grain and growth rings.

          
ConcretePoured stone with a fine, uneven grain.

          
NeonSelf-lit colour. Glows when bloom is on.

          
SandFine matte grains with a warm tint.

          
RubberSoft dark surface with a damped highlight.

          
IcePale, glossy and cold, with a fresnel edge.

          
FabricSoft woven cloth with a matte response.

          
MarblePolished stone with pale veins.

        

        
A union keeps the material of the first part it was built from. Scripts set the same field with the lowercase key: block.Material = "neon". Use Plastic, Glass, Metal, Grass, Brick, Tile, Carpet, Wood, Concrete, Neon, Sand, Rubber, Ice, Fabric or Marble.

        
Lights and shadows

        
A Light is a placeable point or spot light. Point lights shine in every direction; spot lights shine in a cone and use Rotation to aim, with their local +Z direction and a default rotation pointing down. Enabled turns a light on and off, Color sets its tint, Brightness its strength, Range how far it reaches in Vanillameters, and Cone angle the width of a spot beam.

        
Both spot and point lights have Cast shadows. The nearest two shadow-casting lights get a map, and shadow quality follows the Shadows setting. A spot uses one cone map; a point uses a six-face cube map, so its shadow wraps around it. The nearest eight enabled lights are used in the viewport, so a large world stays fast. A small sun marker shows each light in the editor even when it is inside a wall, and a selected light uses the normal Move and Rotate gizmos. Scripts can set Enabled, Color, Brightness, Range, LightType, Shadows, Position and Rotation.

        
Effects

        
Add a SimpleEffect for a ready-made Smoke, Fire, Steam, Dust, Sparkle / Shine, Explosion, Splash or Embers preset, or an AdvancedEffect when you want to control the sprite, size, colour, gravity and emitter shape yourself. Effects are children of the World or of a shape or model; the Position fields are an offset from that parent. Local space makes the particles turn and follow the parent, while World space leaves them where they were emitted.

        
SimpleEffect scales its preset with Size and Speed, and every effect can emit continuously with Rate or fire a Burst. AdvancedEffect adds the sprite or sprite sheet, alpha or additive blend, lifetime, start and end size, spread, gravity, drag, spin, colour over life, fades, emitter shape and radius. Scripts can use Play(), Stop() and Emit(count), and can set Emitting and any of the properties above. Effects animate in the editor and render with the scene during Run.

        
Audio

        
A Sound plays a built-in preset (Beep, Chime, Click, Thud or Siren) or an audio file uploaded in World Settings → Assets. Presets are synthesised, so a world never needs an audio file. Playing starts and stops it, Looped repeats it, Volume is a slider from 0 to 1, Pitch changes its speed and 3D sound turns HRTF panning on. Rolloff controls how quickly it fades with distance, and a looped uploaded file crossfades at the seam.

        
Max distance makes a Sound positional and only applies when the Sound is a child of an object; it is heard within that many meters of its parent. A Sound placed straight in a Space, or one with 3D sound off, is heard at the same volume everywhere. The camera is the listener, so turning and moving changes the left/right and distance cues. With no files, the engine also gives the controlled player footsteps that follow the material under its feet, falling air, landing whooshes and a death sound, and hard body impacts make a material-aware thud. World Settings → Audio can replace any of those with a preset or an uploaded asset, or turn it off. Scripts can change Playing, Looped, Volume, Pitch, Spatial, Rolloff, MaxDistance, Preset and Source, and call Play() and Stop().

        
Multiplayer

        
Press Multiplayer in the toolbar. Host room creates a five-character code; share it with up to four guests. A guest opens Join room, enters the code, and receives the host's current world. The host stays authoritative, relays and checks edit batches, and keeps the tab open for the room to exist. The room has a roster, chat and coloured selection markers, so you can see what another collaborator has selected.

        
Rooms use PeerJS over the free public signalling server and then a direct WebRTC connection. There is no backend to deploy and no account. A restrictive network may need a TURN relay; a host can supply one through window.VANILLA_TURN before loading the editor. Messages are capped, rate-limited and validated, and an editing room pauses its world sync while the simulation runs.

        
The Player page also has Host Lobby and Join Lobby. The host runs the simulation and streams the live world to guests. Each guest gets a simple player avatar that the host moves from that guest's WASD, Space and Shift input; the guest camera follows the avatar, and other objects stay host-owned. Hosting is limited by the host tab staying online, the public signalling service, and the 32 MB world-transfer cap.

        
World Settings

        
Open World ▾ → Settings in the top bar to edit the world itself. The dialog writes to the World Settings instance under World, so the values save with the world and the environment fields stay available in Properties. Audio there sets the master volume and chooses what footsteps, impacts and the player death use: procedural by default, a built-in preset, an uploaded audio asset, or silence.

        
SettingWhat it does

          
WorldNameThe name of the world. A download uses it as the file name.

          
CreatorWho made the world.

          
DescriptionWorld info: a short description of the world.

          
MaxPlayersThe most players a server lets into this world at once, 1 to 100. A new ServerSocket starts with this number as its MaxClients.

          
AssetsFiles uploaded from your computer. Each one is stored inside the .vnw file, so the world carries its assets with it. A preview and file size are shown for each, and you can rename or remove them.

        

        
The Defaults tab edits the Human inside DefaultPlayer: Health, MaxHealth, WalkSpeed, RunSpeed, JumpHeight, Stamina, MaxStamina, RunStaminaLoss, JumpStaminaLoss and StaminaGain. New Humans and the DefaultPlayer template start with these values, and changing a value on the DefaultPlayer's Human updates the same default.

        
The Version tab shows the version the world was Created in, the Current content version, and the Latest engine version. When the world is older, Migrate upgrades its content to the latest version: it adds new built-in scripts such as Networking, rebuilds older union surfaces, and fills in newer fields such as player defaults. Migration never removes instances or overwrites a script that already exists, and it records the new current version in the .vnw file. Worlds created before version tracking show their last saved engine version as the starting point.

        
The Environment tab sets the time of day, gravity and the kill layer.

        
PropertyRangeDefault

Gravity0 to 1000 m/s². Presets: Earth 9.8, Moon 1.62, Space 0, Jupiter 24.89.8

There is no invisible ground at y = 0. Objects fall until they land on something solid or pass the kill layer.

        
File menu and .vnw files

        
The File menu in the top bar saves and opens whole worlds. This browser keeps three saves: Autosave, Browser Slot 1 and Browser Slot 2. Any other save is a .vnw file on your computer. A world file is plain JSON holding everything in World, Storage, Scripts, UI and Communications, including script source. Engine-owned objects such as the Viewfinder are not saved.

        
Offline mode in the File menu builds a ZIP of this editor in the tab and downloads it. Unzip it and open engine/index.html to use the editor without a connection; that copy skips the online update check. Browser saves belong to the address you opened, so download your world as a .vnw before switching and open it in the offline copy.

        
The page checks every 30 seconds whether a newer version of the engine or of Vanillalua has been published. If one has, a prompt offers to save and reload; your world is saved to Autosave first and opened again in the new version.

        
CommandWhat it does

          
Save to Autosave, Browser Slot 1 or 2 Ctrl SWrites that slot in this browser's local storage. Saving again overwrites only that slot. Ctrl S writes Autosave.

          
Download as .vnw Ctrl Shift SDownloads the world as a .vnw file named after it, to share or back up. Anything that is not one of the three browser slots is a file like this.

          
Open Autosave, Browser Slot 1 or 2Replaces the current world with that slot. Empty slots are greyed out.

          
Open .vnw file…Replaces the current world with a file you choose. Invalid files are rejected with a message and nothing changes.

          
Add .vanilla instance…Adds one instance from a .vanilla file: a model, a script or anything else, with everything inside it. The rest of the world is left alone, and an instance whose UID is already taken is renamed.

          
New empty worldClears World, Storage and Scripts, leaving one World Settings.

        

        
Opening and creating ask for confirmation first because they replace everything. There is no undo, so save before you open another world.

        
Premade scripts, models and interfaces

        
The toolbox page holds ready-made scripts, models and interfaces. Each one downloads as a .vanilla file, which you add with File → Add .vanilla instance…: it is added alongside your own instances instead of replacing them, so a premade script, model or interface can be dropped into a world you are already building.

        
A .vanilla file is plain JSON holding one instance at the top of a space, plus any number of children:

        
{
  "format": "VanillaInstance",
  "formatVersion": 1,
  "objects": {
    "MyScript": {
      "type": "script", "name": "My Script", "parent": "scripts",
      "scriptType": "Server", "runWhen": "simulation",
      "language": "vanillalua", "source": "print(\"Hello\")"
    }
  }
}

        
The top instance's parent is the space it goes into: world, storage or scripts. Children name their parent instead, so a model can carry all of its parts with it. A world save cut down to a single instance also works.

        
Childing

        
Any instance can be a child of another instance. The Explorer shows children indented under their parent, with an arrow to collapse them.

        
    
          
  • Drag a row onto another row to make it a child. Drag it onto a space name to move it back to the top level of that space.
    • 
          
  • Use Add Child… or Paste as Child in an instance's three-dot menu to create or paste something directly inside it.
    • 
          
  • Deleting a parent deletes all of its children. Copy, cut and paste carry children along.
    • 
          
  • Reorder by dropping on the top or bottom edge of a row (a line shows where it will land). Dropping on the middle of a row makes a child.
    • 
        

        
Children live in the same space as their parent and keep their own position; they do not move with the parent. A script placed under an object, anywhere inside World, Scripts or a UI element, runs like any other script and can reach that object with script.Parent.

        
A Ball is a smooth 3D sphere with the same properties as a prism: position, size, color, face coloring, face labels, wireframe, locked, and the physics switches. Its Size is the radius on each axis, so it defaults to 0.5 on every axis. When the simulation runs, a ball rolls: it spins to match its speed as it moves over a surface, bounces a little when it lands hard, and keeps its spin while it is in the air. The panels and seams painted on it make the rolling easy to see. Stopping the simulation puts it back the way it was.

        
A Human is a character instance that holds health, movement and stamina values. It is always named Human, and its PlayerName property holds the player's name. A new Human starts with a PlayerName of Player followed by a number (Player1, Player2 and so on), and when its model is given to a player, the model and the PlayerName both become that player's name. It has no body and does not render. These values are used by the player you control, and at 0 Health the player using the model dies. The defaults, set in World Settings → Defaults, are Health 100, MaxHealth 100, WalkSpeed 3.5 Vm/s, RunSpeed 6 Vm/s, Stamina 100, MaxStamina 100, RunStaminaLoss 3 per second, JumpHeight 1.5 Vm, JumpStaminaLoss 20 per jump and StaminaGain 6.5 per second.

        
A Wedge is a ramp: a block with its top-front half sliced away, so it is solid underneath and rises from its front edge up to the top of its back (+Z) face. It has the same properties as a prism, including Color, rotation and the physics switches, and its Size is a half size on each axis like a prism's.

        
The player walks up a wedge's slope at walking pace, and the slope holds things up along its angle, so a ball rolls down it and a box rests on the slope rather than floating at the top of the shape. Only the tall back face is a wall, and the air above the slope is empty: nothing is stopped by the box a wedge would fill.

        
A Cylinder is a round column standing on its ends, with a flat top and bottom. Its Size is a half size too: Width and Length are the radius on the X and Z axes and Height is half the column's height. Rotating it tilts the column, and physics then treats it as the box around it. Untilted, it collides as the round column it looks like: the corners of the square around it are empty air, the player stands on its round top and is stopped by its round side, and a ball rests on the top only where the top really is. Blocks are held by its round top and stopped by its round side too, rather than by the square around it, and a block pushed into the round side slides around the curve instead of stopping square on it as it would on a rectangle. A body dropped squarely onto the round top stays there rather than being shoved off the side. It also weighs by its round volume rather than the square around it.

        
A Union is one solid built from other parts. Select the parts in World, then choose Union Selected in the three-dot menu: they are merged into a single instance and the originals are removed. Turn on Negated (subtract in a union) in a part's properties to cut that part away instead of adding it, and use Intersect Selected to keep only the space every selected part shares. That is how you cut a doorway: build the wall, put a block where the doorway belongs, make that block Negated, select both and choose Union Selected.

        
The union is a real surface built from the parts: blocks, wedges, cylinders, balls and other unions are cut and joined into one continuous mesh, with no hidden blocks and no steps along a slope. Its outline is drawn only along the real creases of that surface: shared vertices are welded and T-junctions are split before creases are found, so the seams where the original parts met are not visible. Cut-out parts stay hollow, and the player is blocked by the surface's cells rather than by the whole box, so a cut doorway can be walked through. The union keeps the size of the parts it was built from, and building a union again from new parts is how you change one.

        
A Sound plays a built-in preset (Beep, Chime, Click, Thud or Siren) or an audio file uploaded in World Settings → Assets. Presets are synthesised, so a world never needs an audio file. Playing starts and stops it, Looped repeats it, Volume is a slider from 0 to 1, Pitch changes its speed and 3D sound turns HRTF panning on. Rolloff controls how quickly it fades with distance, and a looped uploaded file crossfades at the seam. Sounds play while the simulation runs; Stop silences them and restores the world.

        
Max distance makes a Sound positional and only applies when the Sound is a child of an object: it is heard within that many meters of its parent and fades out as the camera moves away, so a Sound inside a block is loud beside the block and silent further off. A Sound placed straight in a Space, or one with 3D sound off, is heard at the same volume everywhere. The camera is the listener, so turning and moving changes the left/right and distance cues.

        
With no files, the engine also gives the controlled player footsteps that follow the material under its feet, falling air, landing whooshes and a death sound, and hard body impacts make a material-aware thud. World Settings → Audio can replace any of those with a preset or an uploaded asset, or turn it off. Scripts can change Playing, Looped, Volume, Pitch, Spatial, Rolloff, MaxDistance, Preset and Source while the simulation runs, and can call Play() and Stop() on a Sound.

        
A Highlight draws an outline around the object it sits inside. Put one inside a model to outline a player, or inside a part to outline just that part. Only the edges the camera can see are drawn: an edge on the far side of the shape is left out, and a wall hides the part of the outline behind it. A cut hole is outlined all the way around its rim. A model's parts are merged into one outline, so its internal part seams do not show. Color sets the outline color, and Appears over objects turns off hiding by other objects and always draws the visible edges on top (on by default), so a player can be seen through a wall; the far side of the shape itself is still left out.

        
A Light is a placeable point or spot light. Point lights shine in every direction; spot lights shine in a cone and use Rotation to aim, with their local +Z direction and a default rotation pointing down. Enabled turns a light on and off, Color sets its tint, Brightness its strength, Range how far it reaches in Vanillameters, and Cone angle the width of a spot beam. Both spot and point lights have Cast shadows; the nearest two shadow-casting lights get a map, and shadow quality follows the Shadows setting. A spot uses one cone map; a point uses a six-face cube map, so its shadow wraps around it. The nearest eight enabled lights are used in the viewport, so a large world stays fast. A small sun marker shows each light in the editor, even when it is inside a wall, and a selected light uses the normal Move and Rotate gizmos.

        
Textures

        
A Texture paints chosen faces of a Rectangular Prism. Use Add Child… in a prism's three-dot menu and choose Texture; it appears as a child of that prism and always affects its parent.

        
    
          
  • Faces – toggle one or more of Top, Bottom, Front, Back, Left and Right. All faces and None are shortcuts.
    • 
          
  • Texture – pick what to apply. For now there is one: Grid, with fine lines every 0.25 Vm, medium lines every 0.5 Vm and bold lines every 1 Vm, which makes squares like a normal grid.
    • 
          
  • The grid is locked to the world, so the lines of neighboring prisms line up and match the origin marker. In the distance the fine lines blend into a soft shade and wider lines every 4, 16 and 64 Vm take over, so the grid stays visible all the way to the horizon without shimmering.
    • 
          
  • The default Plate has a Texture on its Top face. Selecting a Texture outlines the prism it affects.
    •

The script editor

        
Create a Script from a space's + button, or with Add Child… on a UI element, and double-click it to open it as a tab. The editor shows line numbers on the left, your code in the middle, and warning and error markers on the right. The Output panel below shows print results and runtime errors. Tab indents.

        
Script properties split into Execution and Miscellaneous:

        
    
          
  • Script type: Local or Server (see Script types and running).
    • 
          
  • Run when: Simulation start, Client join or Manual call by another script.
    • 
          
  • Language: Vanillalua or JSON. JSON scripts hold data, are checked for valid JSON and cannot run.
    • 
        

        
1. A first script

        
Every Vanillalua script should begin by loading the Scripts space and the Instance module. Add other spaces with call when you need to access them.

        
call Scripts
call World
get Instance

local block = Instance.create("prism6", World)
block.Position = vanilla3D.Position(0, 10, 0)
print("Created:", block)

        
call World loads the World space. get Instance loads the instance API, and get Scripting loads scripting utilities for UID lookup and reassignment. Setup lines belong at the top of the script.

        
2. Variables: local and global

        
local name = value creates a variable scoped to the current script block. A variable assigned without local is a global variable: all scripts can read it while the simulation is running.

        
call Scripts
get Instance

local privateCount = 1
sharedCount = 10
print(privateCount)
print(sharedCount)

        
Global write permissions: the script that first creates a global may update it, and any Server script may update any global. Other Local scripts can read globals but cannot change them. Use a Server script for values that need to be centrally controlled. Global variables are runtime state and are cleared when a new simulation starts or the simulation stops.

        
Use clear, descriptive names for globals to avoid accidentally sharing the same name between scripts. Local variables are best for temporary values and implementation details.

        
# Server script
sharedScore = 0

# Any script can read this:
print(sharedScore)

# The script that created sharedScore can update it,
# and Server scripts can update it too.
sharedScore = sharedScore + 1

        
3. Values and types

        
    
          
  • Numbers: 12, 3.5, 0.25. Decimal literals support up to two digits after the decimal point.
    • 
          
  • Strings: "hello" or 'hello'. Use 
 for a newline and 	 for a tab inside a string.
    • 
          
  • Booleans: True and False.
    • 
          
  • Nil: nil represents no value.
    • 
          
  • Instances: references to objects in the scene, such as the result of Instance.create().
    • 
          
  • Vectors: three-number values used for positions and sizes.
    • 
        

        
Comments start with # and continue to the end of the line.

        
4. Printing output

        
Use print(...) to send values to the Output panel. You can print strings, numbers, variables, instances, vectors, and multiple values.

        
call World
get Instance
local score = 125
local block = Instance.create("prism6", World)
print("Score:", score)
print("Block ID:", block)
print("Position:", block.Position)

        
Instances print their unique ID, such as Cobalt092. Multiple arguments are separated in the output. If an instance has been deleted, its printed value is deleted instance.

        
5. Waiting and timed scripts

        
wait(seconds) pauses the current script for the specified number of seconds. The argument must be a non-negative number with up to two decimal places. Waiting yields to other scripts and the simulation; it does not freeze the whole editor.

        
call Scripts
call World
get Instance

local block = Instance.create("prism6", World)
block.Position = vanilla3D.Position(0, 0, 0)
for i in 1, 5 do
    block.Position.Y = block.Position.Y + 1
    print("Step", i, "Y =", block.Position.Y)
    wait(0.5)
end

        
Use wait(0) to yield without an intentional delay. A long-running while loop yields between iterations, so other scripts can continue running.

        
6. Operators

        
    
          
  • Math: +, -, *, /, %
    • 
          
  • Comparisons: ==, ~= or != (not equal), <, >, <=, >=
    • 
          
  • Logic: and, or, not
    • 
          
  • Grouping: parentheses such as (a + b) * 2
    • 
          
  • String joining: use + when at least one operand is a string, e.g. "Score: " + score.
    • 
        

        
Math operators require numbers, except vector addition/subtraction and vector multiplication by a number. In conditions, nil and False are false-like; other values are true-like.

        
7. Conditions

        
local temperature = 18
if temperature >= 25 then
    print("Warm")
else
    print("Cool")
end

        
Conditions use if, optional else, and end. Comparisons can be combined with and, or, and not. There is no elseif; nest another if inside else instead.

        
8. Loops

        
A numeric for loop includes both its start and end values:

        
for i in 1, 4 do
    print("Iteration", i)
end

        
A while loop repeats while its condition remains true. Make sure something changes the condition so the loop can finish.

        
local count = 0
while count < 3 do
    count = count + 1
    print(count)
    wait(0.25)
end

        
9. Spaces and instance lookup

        
Available spaces are World, Storage, Scripts, UI, Communications, and Players (read-only). Load each with call before using it. Existing instances must be accessed by their unique ID (UID), not by their display name. Use Instance.GetUID(name) to find an ID by object name.

        
call World
get Scripting
get Instance

local blockUID = Instance.GetUID("Block")
local block = World.blockUID
print(block.Name)

        
When a dot member on a Space matches a local variable, its string value is treated as the UID. Bracket lookup also works: World[blockUID]. You can pass the Space to GetUID when names are duplicated, for example Instance.GetUID("Block", World).

        
10. The Instance module

        
    
          
  • Instance.create(type, space) — creates and returns an instance. Supported types: "prism6", "ball", "wedge", "cylinder", "sound", "highlight", "light", "simpleeffect", "advancedeffect", "script", "worldsettings", "human", and the connection types "clientsocket", "serversocket", "peerconnection" and "groupconnection", which can only be created in Communications.
    • 
          
  • Instance.duplicate(instance) — duplicates an instance in its current space.
    • 
          
  • Instance.duplicate(instance, space) — duplicates it into a chosen loaded space.
    • 
          
  • Instance.delete(instance) — deletes the instance. References to it become deleted references.
    • 
          
  • Instance.GetUID(name) — returns the unique ID of an existing instance with that display name. Optionally pass a Space as the second argument to disambiguate duplicates.
    • 
          
  • Instance.SetUID(oldUID, newUID) — changes an instance's unique ID. The new UID must be unique and contain only letters and numbers, starting with a letter.
    • 
        

        
call World
get Instance

local original = Instance.create("prism6", World)
original.Position = vanilla3D.Position(0, 3, 0)
local copy = Instance.duplicate(original, World)
copy.Position = vanilla3D.Position(2, 3, 0)
print("Original:", original)
print("Copy:", copy)
Instance.delete(copy)

        
Find and change a unique ID

        
call World
get Scripting
get Instance

local blockUID = Instance.GetUID("Block")
local block = World.blockUID

Instance.SetUID(blockUID, "Ashburn534")
blockUID = Instance.GetUID("Block")
block = World.blockUID
print(blockUID)
print(block)

        
SetUID rekeys the existing instance; it does not rename the visible Name property. Refresh the UID variable after changing it, then retrieve the instance again. If more than one object has the same name, provide its Space to GetUID.

        
11. Properties and vectors

        
Read or set properties using instance.Property. Properties are validated by the engine, so a property expects the correct kind of value.

        
Applies toProperties

          
Every instanceName (string), Type (read-only), Parent (a Space or an instance)

          
BallsA "ball" has every prism property below. Its Size is the radius on each axis, so the default Size of 0.5 makes a ball 1 Vm wide. Physics treats it as a sphere with the average of its three sizes.

          
RotationFor prisms and balls: a vector of degrees about X, Y and Z, for example block.Rotation = vanilla3D.Position(0, 45, 0). The turn about Y is applied first, then the tilt about X, then the roll about Z.

          
VelocityEvery shape, union, model and Human: a vector you can read or set while the simulation runs. On a model it is the average of its parts; setting it sets every part. For example ball.Velocity = vanilla3D.Position(4, 0, 0) rolls a ball along +X.

          
TouchingEvery shape, union, model and Human has IsTouching (True or False), Touching (the other instance with the strongest current contact, or nil) and TouchingAll (a table of every touching instance). Prism blocksPosition, Size (vectors, each axis at least 0.05 for Size), Locked, Anchored, ReactsToPhysics, Collidable, Wireframe, FaceColoring, ShowLabels (True or False), Color (a hex string such as "#ff8800"; FaceColoring overrides it) and Material (a name such as "plastic", "brick", "glass" or "metal").

          
World SettingsTimeOfDay (0 to 24), Gravity (0 to 1000), KillLayer (number)

SoundsPlaying, Looped and Spatial (True or False), Volume (0 to 1), Pitch (0.25 to 4), Rolloff (0 to 4), MaxDistance (meters, 0 or more, used only when the Sound is inside an object), Preset (one of beep, chime, click, thud, siren) and Source (preset:beep or asset:name). Sounds also have Play() and Stop().

EffectsSimpleEffect and AdvancedEffect have Emitting (True or False), Position (the offset from a parent or a world position), Rate, Speed, and the Advanced settings Burst, Lifetime, SizeStart, SizeEnd, Spread, Gravity, Drag, Rotation, ColorStart, ColorEnd, FadeIn, FadeOut, Blend, Sprite, Image, Frames, FPS, Shape, Space and Radius. Call Play(), Stop() or Emit(count) on an effect. SimpleEffect also exposes its Preset and Color; Size scales the preset.

PlayersCharacter (the player's current model, read-only), ModelAdded (an event; passes the new model), and SkinColor, ShirtColor and PantsColor (hex strings applied to the current model). Use Players.AssignModelToPlayer to give a player a model.

        

        
Chat. Load the chat API with get Chat. Chat.Send("Hello from the server")

    print(message.From, message.Text)
end)

call World
get Instance
local block = Instance.create("prism6", World)
block.Position = vanilla3D.Position(2, 5, 0)
block.Size = vanilla3D.Size(2, 1, 3)
block.Anchored = True
print(block.Position.X, block.Position.Y, block.Position.Z)

        
11b. Parents and the script variable

        
Inside every running script, script is a built-in variable that always refers to the script itself. Its Parent is the object the script sits under, or a Space if it is not inside an object.

        
call Scripts
get Instance

local part = script.Parent
part.Anchored = True
print("Controlling", part.Name)

# Reparent: put a new script inside the block
local child = Instance.create("script", World)
child.Parent = part

        
Read Parent from any instance. Assign it an instance or a Space to move it. An instance cannot become its own parent or a child of its own descendant. If a script is not inside an object, script.Parent is its Space, such as Scripts.

        
12. Script types and running

        
    
          
  • Server: trusted script type for shared/global updates. Server scripts can modify any global variable.
    • 
          
  • Local: can read global variables and modify only globals it originally created.
    • 
          
  • Run When: Simulation: runs when Run starts the simulation.
    • 
          
  • Run When: Join: reserved for join-trigger behavior if supported by the current project workflow.
    • 
          
  • Run When: Manual: starts only when manually invoked, for example through the script's Run property.
    • 
        

        
When the simulation starts, Server scripts begin before Local scripts. A JSON script cannot be run. Stopping the simulation stops active script tasks and restores the scene snapshot from before Run. Runtime globals are cleared as part of ending the simulation.

        
12b. Players, events and threads

        
The Players space lists every player in the game as a read-only Player instance with a Name and a Character; use player.Character (for example Players.LocalPlayer.Character) to read the player's current model. It is empty while you edit. When you press Run, the editor joins one player, Player1, and when you stop, that player leaves. Scripts cannot create, edit or delete players: Players.AssignModelToPlayer is the only way to change a player's model.

        
Use get Players to load the functions and events, and call Players to load the space.

        
    
          
  • Players.Count — the number of players, as a number.
    • 
          
  • Players.Players — a list of the players' names, as strings.
    • 
          
  • Players.AddModel(model) — copies a model (an instance or its UID) and everything in it into World, and returns the copy.
    • 
          
  • Players.AssignModelToPlayer(model, player) — gives the player that model, which is also called spawning. The player's old model is removed first. The model is renamed to the player's name, moved to the spawn position and held in place. player is a Player instance or a player's name.
    • 
          
  • Players.OnPlayerJoin, Players.OnPlayerSpawn, Players.OnPlayerLeave and Players.OnPlayerDeath — events. Each one passes the Player instance.
    • 
          
  • player.ModelAdded — an event on each Player. It passes the new model when Players.AssignModelToPlayer gives that player one. Connect before the model is assigned, or check player.Character if the player already has a model.
    • 
        

        
To wait for the player's model in a Local script, connect player.ModelAdded. The event passes the new model, and player.Character already points to it when the handler runs:

        
call Scripts
call Players
get Instance

local player = Players.LocalPlayer
function setup(character)
    local human = character.Human
    # Connect HealthChanged and StaminaChanged here.
end

player.ModelAdded:Connect(setup)
if player.Character then setup(player.Character) end

        
Listen to an event with :Connect and a function. object:Method(args) is the same call as object.Method(args). Connect returns a connection, and connection:Disconnect() stops listening. Each time an event fires its function runs as its own task, so it can use wait(). A function can be written without a name right where it is used: function(player) ... end. A script that connects late can read Players.Players to find players who already joined.

        
Death. When the Health of a Human inside a player's model reaches 0, the player dies. The model's parts are released so they fall apart, then OnPlayerDeath fires. Giving the player a new model removes the old one.

        
Spawn position. A model spawns with its feet at 0, 5, 0. If one block has Spawnpoint turned on, the model spawns on top of that block instead. Only one block can be the spawnpoint. The editor will not let you pick a second one, and setting a second one in a script prints a warning and is skipped.

        
Playing your player. While the simulation runs you control the first player, the one the editor joins as Player1. W A S D move, Space jumps, Shift sprints, and the Up and Down arrow keys zoom the camera. The camera follows the player's head, and you turn the view with the same camera setting as the editor (Right-drag or Drag). Zoomed all the way in you are in first person: the head is hidden and the rest of the body stays. The model swings round to face the way it moves. Its animation blends Idle, Walk, Run, Jump, Fall and Land; the stride is driven by distance travelled, so the feet stay planted when it is blocked, and idle breathing, torso lean, head look and a landing squash are added procedurally. In first person the head and near arms are hidden, with a subtle head bob. In the air its arms trail behind and its legs tuck up. Walking speed comes from the Human's WalkSpeed, sprinting from RunSpeed and jump height from JumpHeight. Sprinting costs RunStaminaLoss every second and each jump costs JumpStaminaLoss. Stamina comes back at StaminaGain per second while you stand on something and are not sprinting. If it runs out you are exhausted: you cannot sprint or jump, and it comes back at 4 per second (or StaminaGain, if that is lower) until it is full. The player is stopped by anything that is Collidable, walks up slopes and steps up to 0.6 Vm high without jumping, and is stopped by anything taller. Falling below the kill layer sets its Health to 0.

        
Effects. Add a SimpleEffect for a ready-made Smoke, Fire, Steam, Dust, Sparkle / Shine, Explosion, Splash or Embers preset, or an AdvancedEffect when you want to control the sprite, size, colour, gravity and emitter shape yourself. Effects are children of the World or of a shape or model; the Position fields are an offset from that parent. Local space makes the particles turn and follow the parent, while World space leaves them where they were emitted. SimpleEffect scales its preset with Size and Speed, and every effect can emit continuously with Rate or fire a Burst. Scripts can use Play(), Stop() and Emit(count), and can set Emitting and any of the properties above. Effects animate in the editor and render with the scene during Run.

        
Materials. Every shape has a Material in Render: Plastic, Glass, Metal, Grass, Brick, Tile, Carpet, Wood, Concrete, Neon, Sand, Rubber, Ice, Fabric or Marble. Default maps to Plastic. The material changes the surface pattern and how highlights catch it. Color still tints the result, so every material picks up the color you choose. Neon glows when bloom is on, Glass has a bright fresnel edge and Metal is brushed and reflective. A union keeps the material of the first part it was built from. Materials are visual only; they do not change mass or collision.

        
Physics. Everything has the same density, so a body's mass comes from its volume: a ball by its sphere, a cylinder by its round column and a wedge by half its box. Falling bodies speed up with gravity, and air slows them more the faster they go, so every body has a terminal velocity (a person falls at about 55 Vm/s). Air is thick where gravity is strong and gone on the Moon and in Space, so there bodies keep speeding up. When two bodies collide momentum is conserved, so a heavy body pushes a light one much more than the other way round. Fast impacts bounce and lose energy, and sliding bodies slow down and stop because of friction. A body that comes to rest sits exactly on the surface it landed on, so a stack stays still instead of creeping. Turned blocks collide at their real angle, and a union is tested cell by cell, so a hole cut through it is a hole for falling bodies too. Boxes still do not tip over from a collision. The player collides as a box matching its body's width and depth, and a ball is round for the player as well, so corners and turned walls slide instead of stopping on an invisible square. The player is not a body in the simulation: it is moved directly against the world, so nothing it stands on is weighed down by it, and a loose cylinder underfoot simply falls away with the player riding it down.

        
Threads. Scripting.NewThread(fn, threadId, ...) runs fn in a new thread, and any extra arguments are passed to it. threadId is a number, a string, or auto, which uses the next free number. Reusing an id that is still running prints a warning and makes no new thread. A script can have at most the player count times 3 threads made this way. Server scripts share thread ids with other Server scripts, and Local scripts share theirs with other Local scripts.

        
New worlds start with the DefaultPlayer model in Storage (with a Human inside it), a PlayerManagement script that spawns every player who joins and respawns them after they die, and a Networking script that keeps a ServerSocket and one ClientSocket per player in Communications. The Networking script creates the server socket when the simulation starts, adds a ClientSocket named after each player who joins, gives it that player's name in Player, and deletes the socket when the player leaves. It also adopts any players who were already there when it started, so restarting it does not make duplicate sockets:

        
# Networking: keeps a ServerSocket and one ClientSocket per player in Communications.
call Scripts
call Communications
call Players
get Instance
get Players

function findSocket(name)
  return Communications:WaitForChild(name, 0)
end

function makeServerSocket()
  local socket = findSocket("ServerSocket")
  if socket ~= nil then return socket end
  socket = Instance.create("serversocket", Communications)
  socket.Name = "ServerSocket"
  return socket
end

function makeClientSocket(player)
  local socket = findSocket(player.Name)
  if socket ~= nil then return socket end
  socket = Instance.create("clientsocket", Communications)
  socket.Name = player.Name
  socket.Player = player.Name
  return socket
end

makeServerSocket()
Players.OnPlayerJoin:Connect(function(player)
  makeServerSocket()
  makeClientSocket(player)
end)
Players.OnPlayerLeave:Connect(function(player)
  local socket = findSocket(player.Name)
  if socket ~= nil then Instance.delete(socket) end
end)

        
PlayerManagement spawns the models:

        
# PlayerManagement: gives every player a model when they join, and respawns them after they die.
call Scripts
call Storage
call World
call Players
get Scripting
get Instance
get Players

local template = Instance.GetUID("DefaultPlayer", Storage)

function spawn(player)
  local model = Players.AddModel(template)
  Players.AssignModelToPlayer(model, player)
end

function managePlayer(player)
  spawn(player)
  print("Handled new join by " .. player.Name)
end

Players.OnPlayerJoin:Connect(function(player)
  # Every player gets their own thread so they are managed individually.
  Scripting.NewThread(managePlayer, auto, player)
end)

Players.OnPlayerDeath:Connect(function(player)
  wait(3) # The ragdoll lies there for a moment.
  Instance.delete(player.Character)
  spawn(player)
end)

14. Common errors and fixes

        
    
          
  • Missing call Scripts: add call Scripts at the top of every Vanillalua script, or turn on pre-include for it in Settings, Scripting.
    • 
          
  • Missing get Instance: add get Instance at the top if you use instance functions; the editor currently requires this setup line for every Vanillalua script.
    • 
          
  • Space not loaded: add call World, call Storage, call Scripts, call UI, call Communications or call Players before referencing that space.
    • 
          
  • Unknown variable: check spelling and whether the value is local to another script. Use a global assignment (without local) to share a value.
    • 
          
  • Global write denied: only the script that created the global or a Server script can update it.
    • 
          
  • Invalid property value: check that the property name and value type match, e.g. numeric Gravity or boolean Anchored.
    • 
          
  • Invalid wait: use one non-negative number, with no more than two decimal places.
    • 
          
  • Instance deleted: confirm that the instance has not been deleted before reading or changing it.
